# Foundation roadmap · критерии перехода

Проект в фазе **F0 — документирование контрактов**. Таблица — план, не список выполненных функций.

| Этап | Результат | Минимальный критерий |
| --- | --- | --- |
| F0 | роли репозиториев, модель владения, схемы протоколов | ссылки рабочие, JSON валиден, нет конфликта полномочий |
| F1 | прототип терминального 3D + ввод | измерения в терминалах Windows/macOS/Linux/FreeBSD (или честно помеченные непроверенные ОС), SSH, широкое/малое окно |
| F2 | локальный сервер: entity registry + tick + сохранение | тесты воспроизводимости, рестарт без потери подтверждённых событий |
| F3 | одна микролокация, враг, атака, один сюжетный триггер | от создания файла до загрузки: end-to-end, без Blender |
| F4 | observatory → AI proposal → validation → staging → apply/receipt | отказ GitHub, повтор, stale snapshot, конфликт прав, duplicate request |
| F5 | кооператив / отдельный сервер (после ADR) | авторитетные команды, задержка, отключения, безопасность |

## Технические неопределённости

1. Настоящий ANSI/ASCII vs оконный ASCII-фильтр: приоритет **реальный терминал**.
2. Ввод key-up, mouse reporting в разных эмуляторах терминала.
3. Производительность фреймбуфера (diff) при повороте камеры и SSH; измерять p50/p95 throughput.
4. Библиотека рендера: TermGL — кандидат, лицензия/поддержка/quality gate проверяются экспериментально.
5. Фиксированная геометрия, процедурные шаблоны существ и анимации: необходимы библиотеки генераторов и bounded DSL.
6. Сетевая топология, persistence, стратеги совместимости/миграций.
7. Фактические возможности Scheduled ChatGPT + GitHub Connector при доступных правах; **не предполагать**, что он может напрямую вызвать серверное API.
8. Политика приватности, данных и эксплуатационные бюджеты.

## Программа read-only аудита F0

Проверить сценарии: две сессии одновременно; устаревший канон; два конфликтующих региона; ошибочный seed; удалённый referenced ability; ввод вредоносной инструкции из чата игроков; изменение экономики; потеря сети до квитанции; сбой после коммита БД; повтор request; неизвестный тип действия; рестарт во время события; недоступность GitHub; несовместимый клиент.

## Начать практически

Следующий артефакт: автономный тестовый validator + dry-run без сервера и without production writes. **Первый настоящий runtime-прототип — после выбора минимального контракта renderer/input.**
