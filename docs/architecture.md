# ISVELORN · Архитектура Foundation v0.1

**Статус:** принципы утверждены как стартовые границы; конкретные технологии и API пока проектируются. Ссылка на [ADR-0001](adr/0001-foundation.md).

## Цель

Кроссплатформенная терминальная 3D ASCII/ANSI Action RPG; в дальнейшем — кооператив/постоянный мир и регулируемое развитие с Scheduled ChatGPT. Отсутствие ИИ **не останавливает** сервер, боевые действия, сохранения и планировщик событий. Не требуется обязательное ручное моделирование в Blender.

## Владение данными

| Объект | Единственный источник истины | Считывают |
| --- | --- | --- |
| Исполняемый клиент, UI/рендерер | `game` | разработчики, сборки |
| Алгоритмы симуляции, серверные API | `server` | клиент, серверные службы |
| Канон, схемы объектов, определения контента | `world` | сборка, сервер, Director |
| Активные игроки, инвентари, позиции, состояние мира, очередь событий | БД сервера (вне Git) | только авторизованные серверные процессы |
| Роли и политика планировщика ИИ | `director` | Scheduled ChatGPT, контроль публикаций |
| Схемы телеметрии, минимальные агрегаты | `observatory` | Director, проверяющие |
| Пайплайны, доверие, секреты и деплой | `infrastructure` (секреты вне Git) | операторы/CI |
| Общие контракты, ADR, совместимость | `.github` | все репозитории |

**Git — не источник живого состояния мира.** Границы репозиториев не означают обязательные отдельные процессы/серверы. В первой версии все серверные подсистемы могут работать одним процессом.

## Логический маршрут данных

```text
game -> команды -> server (валидация, симуляция, БД) -> состояния -> game
                           |
                  минимизированный экспорт
                           v
                     observatory
                           |
                 Scheduled ChatGPT
                           |
             предложение в director / PR
                           |
                проверки / политика
                           |
          готовый пакет world + версия + SHA
                           |
              инфраструктура доставки
                           |
                   server (apply)
                           |
                    квитанция / сверка
```

**Нет прямого пути ChatGPT → БД.** Снимки и содержимое PR считаются недоверенными входами. Любые исполняемые или административные запросы должны проходить отдельную авторизацию и программу-валидатор.

## Разделение game / world / server

- `game` реализует визуализацию, локальный ввод, разрешённое предсказание и отображение. Не определяет HP, награды, победу, деньги.
- `world` описывает `что` существует: версии, регионы, объекты, способности, шаблоны NPC, сюжет и канон. Не хранит факт состояния конкретного экземпляра.
- `server` определяет `что произошло`: авторитетную физику и столкновения, события, сохранения, прогресс.
- `director` создаёт **предложения**, ограниченные уже реализованными операциями. Новые механики требуют нового кода, тестов и процедуры релиза.

## Постоянство и детерминизм

- Фиксированный tick/упорядоченные события, явный seed и версия алгоритма при процедурной генерации, стабильные идентификаторы.
- Атомарный commit бизнес-операции вместе с idempotency key и квитанцией.
- Серверная очередь событий долговременна; Scheduled ChatGPT **только пополняет или отменяет запланированное по разрешённому протоколу**.
- Репликация случайности или битовая идентичность между ОС **не гарантированы без тестов**: при необходимости используем фиксированный PRNG и целочисленную/фиксированную арифметику в авторитетных расчётах.

## Независимые подсистемы внутри сервера

Simulation & Combat; Entity/Ability Registry; Region & Geometry; Faction/Reputation; Quest/Dialog; Inventory/Economy; Event Scheduler; Persistence/Transactions; Change Application; Telemetry Export. Это **логические обязанности**, не требование микросервисов.

## Версии и эволюция

Foundation: `0.1` (документация). Протоколы данных версионируются **независимо**. Каждая публикация контента имеет manifest, проверенный immutable commit SHA, content revision и требования к версии runtime. Никаких «последних файлов из main» в рабочем сервере. Разрешить только совместимые обновления с планом миграции/отката; прогресс игроков нельзя бездумно откатывать вместе с контентом.

## Не утверждено

Конкретный рендерер (TermGL лишь кандидат), библиотека сети, формат/топология карты, одиночная игра vs кооператив vs MMORPG на первой итерации, экономика, алгоритмы AI-генерации геометрии, политика сроков телеметрии. Для этих вопросов нужны ADR и прототипы.
